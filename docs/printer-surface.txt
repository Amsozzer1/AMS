THE SWAP LOOP (what actually runs per filament change)
------------------------------------------------------
1. printer pauses on M400 U1 and we see it in the report            [OK]
2. routine_unload()          -> unload_filament                     [OK]
3. human (or later, a motor) swaps the spool                        [OK]
4. we watch the printer's own filament sensor until it trips        [OK]
5. routine_confirm_resume()  -> resume                              [OK]
6. cursor advances to the next planned swap                         [OK]
   routine_extrude()  exists but is NOT in this loop — see below    [??]


STARTING A PRINT
----------------
1. FTPS upload the .gcode.3mf to /cache/<name>                                    [OK]
2. project_file with url = file:///sdcard/cache/<name>                            [OK]
   -> NOT ftp:///cache/... ; that faulted the A1 with SD read/write error 0500_C010
3. param = "Metadata/plate_1.gcode" (the gcode inside the 3mf zip)                [OK]
4. use_ams = false, ams_mapping = []  (external spool, never the AMS)             [OK]
5. project/profile/task/subtask ids all "0" = a local LAN print, no cloud         [OK]
6. plate_idx 0, bed_type auto, bed_leveling true                                  [OK]
7. timelapse / flow_cali / vibration_cali / layer_inspect all false               [OK]

THINGS THAT EXIST BUT AREN'T IN THE LOOP

                    Needs a hot nozzle. The real loop closes on the sensor
                    plus resume, and Bambu loads/purges by itself.          [??]
_STAGE_FIELD        defined on the X1/P1 driver, never read by anything.
                    Stage is actually parsed in service.py with the field
                    name hardcoded. Dead code.                             [??]


WHAT WE DELIBERATELY NEVER DO
-----------------------------
never author our own hotend gcode — we ride Bambu's existing change routine
never send a nozzle temperature — unload_filament heats it for us
never send a retract distance — the firmware owns that
never touch the AMS protocol — external spool only
never talk to the cloud — LAN mode, all ids "0"
never read the printer sensor from a module — only the Brain does that


BIGGEST GAPS
------------
X1/P1 driver is guesses end to end — 31 PHASE-0 markers, zero hardware time
FTPS has no unit tests at all; only the live check script exercises it
build_brain(simulate=False) had zero coverage until recently
the filament sensor is the only thing closing the swap loop — no timeout proof at scale
